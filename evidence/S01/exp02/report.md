Two cases make an external edit between inspection and rewrite.

## How results were judged

The oracle (`probes/focus/oracle/oracle.py`) shares no code with the tool and has its own tokenizer for fixture syntax only.

1. Byte oracle. From the original bytes and the declared intent it computes the approved regions itself: the value token for a cost or move, a pure insertion inside the target focus for a link, a pure insertion after the last focus for a new node. Every byte outside those regions must survive in order. BOM, newline style of inserted text and encoding class are checked too.
2. Semantic oracle. The output is re-parsed and compared with the original model plus the intent: IDs, prerequisite groups, mutual exclusions, positions, anchors, costs, shared references, every comment and a hash of every untouched entry.
3. A no-op passes when the source is byte-identical. Other files written are recorded as side effects. A required refusal passes only if the tool refused and no workspace file changed. An edit the tool blocked without touching any file is `refused_safely`.

Self-test `py -3.13 -I -B probes/focus/oracle/selftest.py` ran 16 positive and negative controls. All 16 returned the expected verdict.

## Results

105 checks. 91 pass, 8 refused safely, 6 fail. Two complete runs gave identical output hashes and verdicts for all 105 checks. The 6 failures are 5 edits on the invalid UTF-8 fixture and the stale semantic edit.

## Findings

1. On well-formed trees inside the subset, all four bounded operations change only the value token or an inserted block. BOM, newlines, non-ASCII text, comments, unknown keys and unrelated values survive byte for byte.
2. The no-op leaves the source byte-identical on every input. Every applied rewrite, no-op included, also writes `<file>.focus-plan.json` beside the source. Blocked and refused calls wrote nothing.
3. Files that are not valid UTF-8 fall back to Windows-1252 without a diagnostic. iconv-lite 0.7.3 decodes 0x81, 0x8D, 0x8F, 0x90 and 0x9D to U+FFFD and encodes U+FFFD as 0x9D, so the round-trip guard passes and any edit silently rewrites those bytes to 0x9D.
4. The MCP rewrite always runs with plan authority. After an external change it reported drift status `conflict` and still applied. A formatting-only change survived. A semantic change to another focus was reverted to the plan value.
5. Duplicate IDs block writes with lint blockers. One case refused with `SOURCE_REPLACEMENT_OVERLAP` because the writer indexes focuses by ID.
6. Shared focus definitions are not in the plan. A prerequisite on a shared focus raises `FOCUS_PREREQUISITE_MISSING` and blocks all writes.
7. One missing relative anchor blocks writes to every focus in that tree.
8. Malformed input never caused a write. Inspection of the stray brace file still succeeded and its plan silently omitted the focus after the error.
9. A comment inside a field that must be regenerated causes `FOCUS_UNSAFE_COMMENTED_REWRITE`. A trailing comment beside a scalar is kept.
10. Link insertion and relative to fixed conversion each leave one whitespace-only line inside the approved change. Meaning is unaffected.
11. Full reference and layout lint gates every write. It was the most common reason a bounded gesture was unavailable.

## Supported writable subset

Inputs: a well-formed national `focus_tree` in valid UTF-8 (BOM or not, any newline style) or valid Windows-1252, with unique IDs, every relative anchor present, no prerequisite on a shared focus and every sprite defined.

Operations: no-op, a `cost` change, an `x` and `y` change, adding a prerequisite group where existing prerequisite blocks hold no comment, and appending a new focus.

Host guards needed: reject files that are not valid UTF-8 or clean Windows-1252 before calling the tool. Compare the current hash with the plan's `provenance.sourceHash` right before the call and serialize workspace writes. Treat the sidecar as a declared output.

## Parser limits

Encoding detection is BOM, strict UTF-8, then silent Windows-1252. Unknown keys become raw passthrough entries that the plan cannot change. Scripted constant costs are recognized. Comparison operators stay raw text. Duplicate IDs are imported twice. Shared focus definitions are not imported. After a syntax error the parser recovers and may drop later focuses without saying so.

## Linux image behaviour

All cases ran in the Linux image and two full runs were identical. The upstream focus and source tests ran in a Linux image from the same base digest (`probes/focus/upstream-tests/Dockerfile`, image `sha256:31081edd3273317ff287f66f0169a469cd644bd9fd821285f2cc00c11e978d33`, run as root because `/app` was root-owned). 100 of 101 passed. The 1,024-icon raster test timed out at 300 seconds under CPU contention and was not re-run, so it is a timeout, not a pass. Comparison with a Windows host is unavailable because host builds were excluded. The HOI4 Factory server image does not yet package Agent Tools, so the probe used the upstream image.

## Limitations

Synthetic fixtures only. This is source rewrite evidence, not a game run. The oracle tokenizer covers fixture syntax only. Not probed: compact layout, continuous palettes, mutual exclusion edits, rename, delete, rendering and large trees. Edits went through whole-tree plans taken from inspection.

## Decisions for the maintainer

1. Accept this subset for S04, with shared-dependent, duplicate-ID and orphan-anchor trees inspect-only.
2. Fix the encoding fallback and stale-base behaviour upstream, or rely on host guards only.
3. Allow or relocate the `.focus-plan.json` sidecar inside the mod.
4. Decide whether prerequisites on shared focuses must be writable in the first slice.
