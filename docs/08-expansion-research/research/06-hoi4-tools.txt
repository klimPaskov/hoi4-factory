## 1. Executive findings (read this first)

1. AT is a mature, heavily tested, read/analyse/render plus "one-call rewrite" MCP server (28 tools, MCP Tasks, persistent jobs, HTTP with OAuth/tokens, Docker image on node:22-bookworm-slim). It runs on Linux, needs no desktop, no Steam session and never launches the game. It is directly usable from a Factory server container. [V]
2. AT deliberately has no interactive editor. AGENTS.md of AT says "do not add a dashboard, interactive editor". Event and technology viewers are read-only by design. Factory must build its own browser editors on top of AT's data. [V]
3. For a browser focus editor, AT already exposes almost all structural data as JSON: absolute grid coordinates, position mode (fixed/relative/auto), prerequisite groups (AND of OR-groups), mutual exclusions, branch/lane, source locations, diagnostics, title/icon resolution metadata, layout metrics and a generated-source map. It does NOT expose connector curve geometry as data (only constants and SVG paths) and icon pixels only exist embedded in SVG/HTML/PNG. [V]
4. `hoi4.focus_rewrite` is a whole-plan diff API, not an operation API. You send the complete plan (as exported by `focus_inspect`); the engine computes which focuses/fields changed and patches only those byte ranges. Moving, editing fields, adding, removing and linking (prerequisites, mutual exclusion) are all expressed as plan edits. There is no dry-run flag, no per-property edit call and no undo call. [V]
5. The #42 source-preservation guards exist at fbc5144: `FOCUS_SOURCE_CHANGED_SINCE_PLAN` (stale semantic edit refused, no override) and `SOURCE_ENCODING_NOT_ROUND_TRIPPABLE` (Windows-1252 undefined bytes). Both have unit and integration tests. Factory specs 006/007/009 still cite the older pin 25f5641 that lacks them. [V for code and tests; I for the "#42" label]
6. There is no single "whole-mod unresolved identifiers" report. A shared SymbolIndex (46 symbol kinds) and a ReferenceRecord table exist, and unresolved references to a small set of kinds become `INDEX_UNRESOLVED_REFERENCE` diagnostics, but `hoi4.mod_index` only returns counts/namespaces/next free ID, and `hoi4.impact_inspect` requires at least one symbol, file or proposed source. Domain tools (event lint, focus lint, tech lint, GUI, map) report their own missing references. Cross-kind coverage (decisions, ideas, characters, scripted effects used by name) is partial. [V]
7. Live Tools cannot run on a Factory server. The only tools that fire events, run console commands, read variables from saves and capture event windows are in the Windows-only Python package, which drives a visible game window with SendInput, PrintWindow/ffmpeg capture and Windows OCR. The Rust Linux preview needs an X server and one exact game build, enables no mods, reports "mod_qa: separate; unavailable in this runtime", and has only been exercised in an emulated VM at 512x288. Desktop-only, on the user's machine. [V for the installer, tool count, console mechanism, mod_qa string, config; D for the rest]
8. Mod Setup v0.8.0 has a server-oriented facade (`hoi4_mod_setup::service`) that builds without Tauri and is what Factory's `crates/setup-adapter` consumes. It supports scan, evidence approval, analysis record, plan, hashed approval, conflict decisions, journaled apply with quarantine, and rollback/recovery. Constraints: a confirmed analysis record is required before apply; new-project apply is blocked by the launcher registration requirement (import works); any `scan.*` conflict (symlink, case collision) makes the scan partial and blocks the whole import; update/repair/remove builders live only in the desktop-only `commands.rs`. [V for gates and facade doc; D for line numbers]
9. `hoi4-mod-setup.manifest.json` is NOT written into a mod. It is the upstream source manifest in klimPaskov/Agentic-HOI4-Modding. The per-mod record is `.hoi4-mod-setup/install.lock.json`. The checked-in snapshot docs/source-manifest/hoi4-mod-setup.manifest.json is schema 5.0.0 and stale (live format is 6). [V]
10. Docs versus code: mostly accurate. Mismatches found are listed in section 6.4; the important ones are LT tool count (docs 43, code 47), LT default mode (docs "test", config.json "campaign"), AT docs listing `event_render`/`tech_render` as "Writes: -" although they store artifacts, and AT third-party notices omitting the LGPL libvips binaries pulled in by sharp.

## 2. HOI4 Agent Tools (AT)

### 2.1 Identity, runtime and packaging [V]

- TypeScript ESM, Node ^22.19.0 || ^24.0.0 (package.json `engines`). Apache-2.0. npm package `hoi4-agent-tools`, MCP registry name `io.github.klimPaskov/hoi4-agent-tools` (server.json).
- Binaries: `hoi4-agent-tools` (stdio), `hoi4-agent-tools-http`, `hoi4-agent-tools-setup`.
- Dockerfile: node:22-bookworm-slim (digest pinned), runs `node dist/bin/http.js`, `EXPOSE 3210`, non-root user.
- Native/binary deps: `sharp` 0.35.5 (libvips prebuilt, includes linux x64 and arm64), `tesseract.js` 7 (WASM OCR for map reference images), `fontkit`, `iconv-lite`, `jose` (OAuth), `express` 5, `zod` 4.6.7, MCP SDK 1.32.1 plus `@modelcontextprotocol/*` 2.x.
- Protocol: serves 2025-era clients through a stateful adapter and 2026-07-28 clients through a "modern operation/task adapter", on stdio and HTTP (docs/jobs.md). Optional MCP Tasks negotiated; clients that do not negotiate get ordinary synchronous results.
- Tool naming: dotted (`hoi4.focus_inspect`). Many LLM provider APIs restrict function names to `[A-Za-z0-9_-]` (general knowledge, not from the repo), so Factory's broker needs a name map. [I]
- `tools/list` size: the 2026-10-11 audit (docs/plans/tool-audit.md) measured 70 KB for 28 tools (41 KB of it input schemas). Factory should expose per-task subsets. [V]

### 2.2 Architecture facts that matter for reuse [V]

- Parser: project-owned lossless lexer and concrete syntax tree over original bytes (`src/hoi4_agent_tools/core/source/lexer.ts`, `parser.ts`; ADR 0002). Trivia, duplicate keys, ordering, unknown assignments, operators and exact byte ranges are kept. Edits are non-overlapping byte-range replacements. Nesting limit 256, file limit 32 MiB (`core/source/limits.ts`: SOURCE_MAX_NESTING 256, SOURCE_MAX_BYTES 33,554,432). Localisation has its own BOM-aware line grammar (`core/source/localisation.ts`). Encodings: UTF-8, UTF-8 BOM, Windows-1252 (`core/source/encoding.ts`).
- Index: `SymbolIndex` (core/index.ts) with `SymbolKind` of 46 values (focus_tree, focus, continuous_focus(_palette), decision(_category), event, idea, leader, formable, scripted_effect, scripted_trigger, script_constant, mtth_variable, ai_strategy(_plan), sprite, texture, gui_element, scripted_gui, technology(_folder/_category/_tag), equipment(_module), sub_unit, unit_category, building, ability, combat_tactic, doctrine_*, localisation, variable, flag, event_target, state, province, province_color, strategic_region, adjacency, supply_node, railway). Layers: game, DLC, dependencies, mod, with load order and `replace_path` handling (config doc).
- Reference edges recorded in the core index (ReferenceRecord) are limited to: technology and tech folder/category/tag/building references, focus prerequisite, focus exclusion, focus relative_position_id, focus/continuous-focus icon to sprite, gui sprite to sprite, scripted_gui window to gui_element, state to province. Event-call, scripted-effect-call and decision/idea edges are produced by separate domain/semantic scanners (event/source-analysis.ts, core/impact-semantic.ts, core/semantic-dependencies.ts), not by the core ReferenceRecord table. (core/index.ts lines ~800-1360, `addReference` call sites)
- Artifacts: content-addressed, provenance-stamped, stored under `workspaceStorageRoot/<id>/artifacts` (or `.hoi4-agent/artifacts` inside the mod when `workspaceStorageRoot` is unset; docs/configuration.md). Served as MCP resources `hoi4-agent://workspace/{workspaceId}/artifact/{sha256}/{provenanceHash}/{name}` with `?offset=&length=` ranges (docs/tools.md). Inline results are capped at 32 KB structured content; pictures are never inline.
- Transactions: all mod writes go through `core/transactions.ts` (atomic replace, stale-source check, journal, rollback; ADR 0007, 0047). Public API never exposes transaction ids, plan hashes or apply tokens (AT AGENTS.md "Engineering boundaries").
- Isolation: workers are separate Node processes with fixed registered operations; HTTP has principal-to-workspace grants, Origin/Host validation, scopes `hoi4:read`/`hoi4:write`, static tokens (always read+write) or OAuth/OIDC (docs/http.md, tests/integration/http-authorization.test.ts, http-security.test.ts).

### 2.4 Direct answers to the specific questions

#### 2.4.1 Does `hoi4_mod_index` or `hoi4_script_validate` build a symbol index / reference graph and report unresolved identifiers? Duplicates?

- `hoi4.mod_index` (reference/mod-index.ts): calls `engine.scan(...)` which builds the full SymbolIndex, then only reports counts per kind, folder totals, event namespaces and the next free id. It does not return symbols, references or diagnostics. `next_id` scans every layer so a new id cannot collide with game or dependency ids. [V]
- `hoi4.script_validate`: does not build a reference graph. It checks syntax, command kind and scope against installed documentation. Unknown helpers and native argument blocks stay `unresolved` (valid: null). It treats the mod's scripted effects and triggers as known commands (reference.md) but does not check that event ids, focus ids, localisation keys or sprites referenced inside bodies exist. It adds seven known-mistake rules, one of which (`event_namespace_missing`) is a missing-namespace check. [V]
- The shared SymbolIndex does emit diagnostics: `INDEX_UNRESOLVED_REFERENCE` (error) or `INDEX_UNRESOLVED_REFERENCE_PARTIAL` (warning when a skipped source could define it), only for references that originate in workspace-owned sources, and `INDEX_SYMBOL_COLLISION` (error) when several active definitions share a key at the same load level in workspace-owned files (core/index.ts around lines 1560-1620). Reference kinds covered are the ones listed in 2.2. These diagnostics surface through domain tools (event graph, tech graph, map validation, post-write validation), not through a dedicated whole-mod tool. [V]
- Per-domain checks (codes found in source): event lint (EVENT_REFERENCE_MISSING, EVENT_HELPER_UNRESOLVED, EVENT_DYNAMIC_DISPATCH_UNRESOLVED, EVENT_DUPLICATE_ID, EVENT_LOCALISATION_MISSING, EVENT_OPTION_DANGLING, EVENT_SCOPE_MISMATCH, EVENT_GATE_WITHOUT_WRITER, EVENT_TARGET_READ_BEFORE_SAVE ...), focus lint (FOCUS_PREREQUISITE_MISSING, FOCUS_RELATIVE_TARGET_MISSING, FOCUS_ICON_REFERENCE_MISSING, FOCUS_LOCALISATION_REFERENCE_MISSING, FOCUS_GAMEPLAY_REFERENCE_MISSING, FOCUS_DUPLICATE_ID, FOCUS_DUPLICATE_COORDINATE, FOCUS_PREREQUISITE_CYCLE, FOCUS_UNREACHABLE ...), tech lint (TECH_*_MISSING, TECH_DUPLICATE_ID, TECH_PREREQUISITE_CYCLE ...), GUI (GUI_MISSING_SPRITE, GUI_MISSING_TEXTURE, GUI_MISSING_LOCALISATION, GUI_REFERENCE_UNRESOLVED ...), map (MAP_*_DUPLICATE). [V]
- Gaps (inference from the absence of codes in the source listing): no checker I could find for missing localisation keys of decisions, ideas or characters; no cross-kind "scripted effect/trigger used but not defined" report outside event/tech helper analysis and `script_validate` unresolved flags; no whole-mod report that lists all unresolved identifiers by kind. [I]
- `hoi4.impact_inspect` is the closest thing to a reference graph. Per docs/analysis.md it "connects source-backed event, focus, decision, idea, technology, scripted-helper, localisation, GUI, sprite, and texture references where a typed static edge can be established", with unresolved dynamic names, missing definitions, skipped sources, cycles and traversal limits explicit. It is seeded per symbol/file, bounded (64 seeds), not a global dump. [V for schema, docs; I for global use being awkward]

#### 2.4.2 What does `hoi4_focus_rewrite` support?

All three are done by sending a plan (JSON validated by schemas/focus.ts, published as schemas/focus-plan.schema.json). The plan carries `provenance.sourcePath/sourceHash/importedPlanHash`, which the drift guard uses.
- Create a tree or palette in a new file (`createIfMissing: true`; refuses to repurpose an existing file: `FOCUS_CREATE_REQUIRES_NEW_SOURCE`). For continuous palettes a plan is mandatory and `layoutMode` must stay `authored`.
- Edit fields: `updateFocusTreeSource` (focus/source-update.ts) computes, per focus, which field projections differ between the imported plan and the target plan (icon, cost, availability, bypass, allow_branch, completion_reward, ai_will_do, search_filters, prerequisites, mutually_exclusive, position, and so on) and replaces only those assignment byte ranges; focuses not in the plan are removed, new focuses are appended; unchanged text is untouched. [V]
- Move nodes: change `position` (mode fixed with x,y; mode relative with relativeTo; mode auto). The layout engine (focus/layout.ts) resolves relative anchors to absolute grid coordinates. In `authored` mode fixed/relative/pinned positions are preserved and automatic ones are placed collision-free. [V]
- Add/link focuses: add a focus object and set its `prerequisites.groups` (each group is an OR list, groups are ANDed) and `mutuallyExclusive`. [V]
- Compact reflow of an existing tree with no plan: `layoutMode: "compact"` + `treeId` (rejects `createIfMissing`). Optional `compactFocusIds` (bounded repair), `pinnedFocusIds` (anchors), `symmetryGroups` (<=64). Refuses invalid geometry (overlap, bad parent order, crossings, connectors through nodes, off-centre canvas). [V]
- Refusals relevant to Factory (source-update.ts): `FOCUS_UNSAFE_COMMENTED_REWRITE` (the assignment to change contains a `#` comment), `FOCUS_UNSAFE_RAW_TREE_REWRITE` / `FOCUS_UNSAFE_RAW_FIELD_REWRITE` / `FOCUS_UNSAFE_RAW_PALETTE_REWRITE` (raw passthrough of unknown fields differs), `FOCUS_UNSAFE_SCALAR_REWRITE`, plus parse-error refusals and the two #42 guards. [V]
- Side effect to plan for: each rewrite also writes `<source>.focus-plan.json` (planning sidecar: branch, lane, pinned, reveal, working labels, AI route flags) beside the focus file inside the mod (focus/planning.ts `focusPlanningSidecarPath`; service.ts lines ~444-660). HOI4 ignores it, but it enters the repo that Factory treats as source of truth. [V]
- Not supported: per-property micro-edit call, dry-run/preview, undo/rollback call (transactions are internal), rename-with-reference-closure, editing shared focuses beyond ids, inline scripts. No x/y handling for `@constants` (see 5.2). [V/I]
- Background use: `requestKey` is accepted for background rewrites (see 2.4.6).

#### 2.4.3 What layout/render data does a browser focus editor need, and what is exposed as data?

Exposed (all JSON, all deterministic, all verified in code):
- `focus-inspect.<rev>.json` (focus/tool-operations.ts ~line 700): `schemaVersion`, `revision`, `plans[]` (full FocusTreePlan), `layouts[]` ({treeId, layout{nodes[{id,x,y,laneId,preserved,sourceMode}], decisions[], diagnostics[], metrics, connectorMeasurements, layoutHash}, diagnosticCount, scenario?}), `continuousFocusPalettes`, `presentation` (resolved titles/descriptions with source locations and icon metadata without pixel data), `sourceHashes`, `diagnostics`.
- Per focus in the plan (schemas/focus.ts): id, label, branchId, laneId, `prerequisites {operator:'and', groups:[{operator:'or', focusIds, rawPassthrough, sourceLocation}]}`, `mutuallyExclusive[]`, `routeLocks[]`, availability/bypass/allowBranch raw blocks, `position` (fixed/relative/auto), visibility, reveal, convergence, sharedSupport, icons[{kind static|dynamic, sprite}], localisation{titleKey, descriptionKey, workingLabel}, ai, filters, links (decision, decision_category, event, idea, leader, formable, helper), cost (number or `@constant`), completionReward, sourceLocation, rawPassthrough.
- `*.focus.json` from focus_render (render.ts `svgDocument`, `graph`): tree header, `layout` (hash, nodes, decisions, metrics, connectorMeasurements), `focuses[]` with position, `prerequisiteGroups`, `mutualExclusions`, branch, lane, visibility, convergence, `terminal`, ai, filters, icons, localisation, `resolvedPresentation`, links, sourceLocation; `diagnostics`; `sourceHashes`; `generatedSourceMap`.
- `*.focus.source-map.json`: generated ranges mapped to plan nodes and imported source locations.
- Coordinates: integer grid units (HOI4 x,y). Pixel constants in geometry.ts: 176 px per column, 116 px per row, node 144x76. Render adds padding 80 by default.
- Diagnostics have codes, severity, category and `location`.

Not exposed as data (gaps for a custom canvas):
- Connector curve geometry (bezier/path points). The SVG contains the path strings and `focusConnectorCurve` exists in geometry.ts, but JSON gives only spans (`connectorMeasurements`: horizontal/vertical/manhattan spans and a `long` flag). A Rust/React canvas must re-derive curves or reuse the SVG. [V]
- Icon pixels: only embedded as data URIs inside SVG/HTML and in the PNG; decoded only when `png` is true (`decodeIcons: rasterize`, tool-operations.ts lines ~841 and ~896). With `png:false`, SVG shows "ICON" placeholders. No separate icon endpoint. Factory's game-reference rules (spec 006: raw game files are never served) therefore need a deliberate decision about serving derived icon crops. [V/I]
- A per-focus "type" for shared focuses: `sharedFocusIds` is a list of ids only. [V]

#### 2.4.4 Event, decision, tech, GUI, map specifics

#### 2.4.6 Jobs and `requestKey` (docs/jobs.md, core/job-*.ts) [V]

- Domain tools run in separate worker processes; warm workers stay `jobWorkerIdleSeconds` (default 180). Heap ceiling `jobWorkerMaxHeapMiB` (default quarter of RAM, 2-8 GiB).
- Persistent tasks need an operator-owned `serverStateRoot`. Task ids are opaque, authenticated and principal-private.
- A native background rewrite MUST carry a caller-generated `requestKey` (1-256 chars). The receipt namespace is scoped to principal + workspace identity + roots and binds tool, inputs and tool version. Same key + identical request returns the same task and result; same key + different inputs fails explicitly. Mutation receipts stay durable after visibility expires so a retry cannot duplicate a write. Ordinary synchronous rewrites do not need a key.
- Commit boundary: the server binds an applied rewrite to its transaction journal before replacing source; after a crash it reads the journal and reconstructs the result without replanning. Cancelling a rewrite after the commit boundary reports the real outcome.
- Read-only jobs have a deadline (`jobDeadlineSeconds`, default 1,800, `JOB_DEADLINE_EXCEEDED`) and cancel grace (`jobCancelGraceSeconds`, default 10). Rewrites are never killed by the deadline. `maxSharedTools` (default 4) and `maxConcurrentTools` (default 2 over HTTP) bound parallelism.
- For Factory: matches spec 006's "reconcile job or receipt before retrying" and "tool protocol must negotiate task support". The key must be stable per intended operation; Factory's C-04 operation id is a natural source. [I]

### 2.5 Determinism and source-preservation guarantees [V unless marked]

- Determinism: AT AGENTS.md requires stable sorting, canonical JSON, seeded algorithms, fixed render inputs, content-addressed artifacts. Acceptance test "stores byte-deterministic HTML, SVG, real PNG, and JSON artifacts through FocusWorkbench" (tests/acceptance/focus-acceptance.test.ts). Seeded GUI scenario generation. PNG bytes depend on sharp/libvips version, so byte equality across a version upgrade is not guaranteed. [I]
- Source preservation: no-change round trip returns the original bytes (tests/unit/core-source.test.ts: "preserves every byte, comment, duplicate key, ordering, and unknown block on no-change round trip"; property tests with fast-check in tests/unit/source-property.test.ts "round-trips arbitrary safe unknown fields, duplicate keys, comments, BOMs, and newlines byte-for-byte"); targeted edits keep BOM/CRLF/Windows-1252 elsewhere; malformed source is not rewritten; unrepresentable edits are refused.
- #42 guards:
  - `FOCUS_SOURCE_CHANGED_SINCE_PLAN` (focus/drift.ts `assertNoSemanticSourceDrift`, `hasSemanticSourceDrift`): a plan imported from an older source revision cannot overwrite a semantic change made since; formatting-only changes and sources already equal to the plan are accepted; there is no override. Applies to trees and continuous palettes. Tests: tests/unit/focus-source-drift-guard.test.ts (4 tests), tests/integration/mcp-focus-source-guards.test.ts (4 tests: stale semantic edit refused, accepted after re-import, formatting-only external change preserved, Windows-1252 edit leaves every other byte unchanged).
  - `SOURCE_ENCODING_NOT_ROUND_TRIPPABLE` (core/source/encoding.ts): a file that is not valid UTF-8 and contains bytes 0x81, 0x8D, 0x8F, 0x90 or 0x9D cannot be rewritten (iconv-lite would otherwise write 0x9D for each); reads still work and carry a warning. Also applied to map text tables. Tests: tests/unit/source-encoding-guards.test.ts (6 tests).
  - CHANGELOG 4.5.0 (2026-10-25) states both and says "Reported by the HOI4 Factory S01 EXP-02 probe". I tie "#42" to these two entries by that text and by Factory's own record (maintainer-decisions-2026-10-24.md line 206; GOAL-S03 line 31). [I for the PR-number mapping]
- Concurrency/staleness primitives available: scan `revision` (sha256) and `expectedRevision` on impact/decision/etc., `expectedSourceHash` on proposed sources, GUI `GUI_SOURCE_STALE`/`GUI_EXPECTED_SOURCE_HASH_REQUIRED`, transaction `TRANSACTION_STALE`.

### 3.3 How it attaches to the game [D unless tagged]

Python/Windows - everything outside the game except an optional telemetry mod:
- Launch: starts `hoi4.exe` directly with `subprocess.Popen` (game/process.py). Whether the Steam client must run is unknown.
- Input: Win32 `SendInput` with scan codes after bringing the window to the foreground (platform/windows_input.py).
- Capture: `PrintWindow(PW_RENDERFULLCONTENT)` then ffmpeg `ddagrab` fallback (client must be fully visible for the fallback).
- OCR: Windows OCR through a persistent PowerShell host; config `ocr.language: en-US`.
- Console: toggled by the grave key (`console.toggle_key: grave` in config.json; game/console.py [V]); command text is pasted via clipboard because typed characters drop; responses are read back by OCR. Commands used: `event <id> [TAG]`, `eval_effect`, `tag`, `save`, `pause_in_hours`.
- Telemetry mod: `hoi4live_telemetry` is generated into `<user_dir>/mod/` (telemetry/modgen.py [V]); its `on_daily`/`on_weekly` scripts for the player country `log` flat-JSON `HOI4LIVE "k":"day",...` lines into `game.log`, which the server tails; registered variables/flags go into `watch` lines. It edits `dlc_load.json` (backups kept). Event lines cover war, peace, faction, annex and control changes, not custom mod events.
- Logs: tails error.log, game.log etc. by byte-offset marks. Saves: plain-text `.hoi4` parsed offline (variables, flags, diffs).
- `hoi4_memory`: bounded read-only Windows process snapshot.

Rust/Linux preview:
- State: `process_vm_readv` on a game it launched as child; checks /proc identity, ELF build id, SHA-256 (platform/linux.rs). Input: X11 XTEST via x11rb at a hard-coded 512x288 profile. Launch: game executable with `-userdir=<fresh dir>`, `env_clear`, DISPLAY/XAUTHORITY, `SDL_AUDIODRIVER=dummy`, fresh `dlc_load.json` with `enabled_mods: []`. Clients connect over a 0600 Unix socket. No screenshots, no memory writes, no raw click tool.
- docs/OWNED_LINUX_LAUNCHER.md [V]: prerequisites include a licensed installed game, the exact Linux x86_64 build (a different hash or build id is refused), "a task-owned local X11 server with its actual PID ... it does not provision or discover a desktop".

### 4.4 Plan / apply / recovery

- `InstallationPlan`: operations (Create, Replace, Merge, Rename, Skip, DeleteManaged, Generate, Chmod, External), conflicts, external_actions, generated_artifacts, download_ledger, approvals, source identity, git_setup, transaction stages (12), root-identity binding. [D]
- Approval is a hash of the exact plan; any conflict decision withdraws approval; apply consumes it; builder output must be unapproved and write nothing outside the project root. [V from facade doc]
- Journal and backups live under the state root, not in the project (paths.rs:116-124 [D]); partial apply allows rollback only (resume and discard refused) (facade doc `recover` row, V). Unresolved incomplete journals block new transactions. Fault-injection hooks at every stage boundary. [D]
- Hard gates for Factory: (a) apply requires "a confirmed selected-provider analysis" except pure removals (transaction.rs:267, V); the facade accepts a host-supplied reply via `record_analysis` through the same validator (V from doc); (b) account-tool providers (codex, Claude account, Gemini/Grok CLI) are refused on the server (doc row `analyze`, V); (c) new-project apply stops at `launcher.registration` because the launcher `.mod` lives in the player's mod folder (builder_tests.rs, V); imports apply. (d) `DefaultPlanBuilder` does not read `install.lock.json`, so rerunning it on an already prepared mod treats edited managed files as unbased conflicts [D, I]. Update/repair/remove plan builders are in `commands.rs` (desktop feature); only building blocks (`update_operations`, `repair_operations`, `managed_removal_operations`) are public in `transaction.rs`. [D]
- Platform readiness difference: `mcp.hoi4_agent_tools` selected but not set `ready` blocks readiness only when the host is Windows (`cfg!(target_os="windows")`); macOS reads as `unsupported_platform`; a Linux server with no runner passes readiness but installs nothing [D, I]. Matches Factory CLAUDE.md note.

### 4.5 Manifest, lock, reimport

- Upstream manifest `hoi4-mod-setup.manifest.json` (RemoteManifest, models.rs:368): schema_version, manifest_id, generated_for_revision, repository, components[] (id, category, source{kind,path,include,exclude,template_engine}, destination{path,ownership}, dependencies, platforms, required_tools, expected_files[{path,sha256,size}], conflict_policy, validation, update{strategy,remove_obsolete}), profiles[], wiki, update_policy, signing, coding_environments[], image_generation, live_testing. Schemas are closed (docs/schemas/remote-manifest*.json). `signing.required=true` is rejected: signature verification is not implemented (manifest.rs:820-826 [D]). The checked-in snapshot is schema 5.0.0, generated for revision 4ce68a2f, 60 components (51 managed, 9 merged), 1,665 expected files, 85.8 MB. [V]
- Per-mod record `.hoi4-mod-setup/install.lock.json` (InstallationLock, models.rs:1099 [D]): schema_version "1.0.0", project_id, script_prefix, primary_namespace, source{repository, mode latest|pinned_commit|pinned_release, revision, manifest_sha256}, coding environment selection, components[], files[] (path, component_id, source_path/revision/sha256, base_sha256, installed_sha256, ownership, preserved_local, installer_created ...), merge_choices, local_modifications, rollback_records. - Reimport/update: current files skip, unmodified replace, missing create; user edits with nothing new from source are "keep_reviewed_edit" and not asked again; CLAUDE.md/AGENTS.md are three-way merged from a base rebuilt at the recorded revision; repeated update with nothing new yields zero conflicts (docs/USER_GUIDE.md "Existing mods" [V], unit tests in repo [D]). Review record is Windows-only (docs/development/2026-10-24-app-review.md [D]).

### 4.6 What it installs into a mod (snapshot 5.0.0 numbers [V]; live format-6 contents not available locally)

- Instructions: CLAUDE.md (canonical, merged) and AGENTS.md projection from templates filled with mod name, prefix, game dir, Workshop dir.
- Skills/agents: 32 skill directories under `.claude/skills/` and 23 agent files under `.claude/agents/` in the snapshot manifest (my count from expected_files; the delegated pass said 25 and 19), plus `.claude/settings.json`, agent-map; generated projections for `.agents`, `.codex`, `.cursor`, `.qoder`, `.opencode`; format 6 adds more clients.

- Tools: in-project `.tools/sync/*.py`, `.tools/check.py`, `.tools/mcp/` bootstrap, `docs/`, `paradox_wiki/` (188 files, ~3.7 MB, manifest marks licence `not_found`), tool settings adapted from mod name/prefix. Outside the project: `hoi4-agent-tools@4.0.3` in the snapshot (pinned with sha512, installed into the user npm prefix by the Python bootstrap, Windows and Linux only); the snapshot's `live_testing` providers are `clausewitz_mcp` (native Linux 1.19.2), `hoi4_live_tools` v1.1.0 (Windows, experimental) and `none`.
- Descriptor/thumbnail generation if missing; managed `.gitignore` block (ignores .tmp/, .agents/, .codex/, .tools/, paradox_wiki/, AGENTS.md, .hoi4-mod-setup/backups/, cache/; CLAUDE.md and .claude/ stay tracked [D]). ### 4.7 Existing-mod import specifics [D]

Existing .git: read bounded, hardened git; linked worktree warns; `.git` symlink blocks; Initialize over existing is refused (Preserve default). descriptor.mod at root parsed; launcher `<id>.mod` discovery only in the root's parent (<=512 entries) and not in the facade. Workshop mods: `remote_file_id` kept; tested on copies of three Workshop mods (Windows). Any folder layout accepted; only setup-relevant paths inventoried. Descriptors must be UTF-8; localisation encoding classified, never rewritten; merge keeps local line endings, generated files are LF. Case collisions and symlinks (including Windows reparse points, so possibly OneDrive placeholders) are block-severity `scan.*` conflicts; on the facade path any `scan.*` conflict except sensitive/profile/four git ids makes the scan `partial`, and a partial scan approves no evidence, so one symlink or case collision in a setup-relevant path blocks the whole import. Windows paths over ~260 characters are a documented limit.

### 4.8 Security [D unless noted]

`RootedDir` no-follow `openat` (Unix) / retained handle + file id (Windows); plan binds the root identity; untrusted git config (`include`, `includeif`, `filter`, `alias`, `url`, `credential`, `core.hookspath/fsmonitor/sshcommand/excludesfile/attributesfile/pager`) refused before git runs and system/global config disabled; subprocesses: exec + argv array, `env_clear`, exe sha256 pinning, timeouts, output caps, Windows Job Object; persisted JSON refused if credential-shaped.

### 4.9 Maturity and licence

~909 `#[test]` functions (grep), fuzz targets (6, compile-only in CI), CI on ubuntu/windows/macOS, protected main, single maintainer, no 1.0. Facade tests use a synthetic fixture package (`service/fixture.rs`); no facade test against the real Agentic package was found [D]. Documented mismatches: docs/14_transaction_rollback.md says journals are under the project but code uses the state root; scan-result schema lacks `case_collision`/`secret_excluded`; DEVELOPMENT.md still says "Planned toolchain". Licence Apache-2.0; no GPL/AGPL in THIRD_PARTY_NOTICES.md; MPL-2.0 present (cssparser, selectors, dtoa-short, option-ext, arriving via dom_query and dirs-sys); `r-efi` MIT OR Apache-2.0 OR LGPL; the wiki snapshot has `license_status: not_found`. Embedding is by git dependency (no crates.io release indicated). [D]

### 4.10 What Factory can reuse for import

- Best fit: `hoi4_mod_setup::service` with `--no-default-features`: scan, per-account session isolation, root-identity binding, hashed plan approval, conflict decisions, journaled apply with quarantine, rollback and recovery. This is what `crates/setup-adapter` already wraps in Factory.
- Standalone pieces: core `merge.rs`, `descriptors.rs`, `manifest.rs` (selection and hash verification), `profile.rs` and `proposals::detect`, `safe_fs` and git hardening if exposed.
- Factory must still: enumerate, hash and Git-commit the mod's own files; produce an analysis reply that passes the validator; keep unmanaged files out of Setup-owned paths; serialize per project (no cross-process lock seen); decide whether hosted workspaces want the agent-tools/bootstrap/check.py parts at all (without a runner, `.mcp.json` and `.codex/config.toml` would point at a package nobody installed) [I].

### 5.2 Outdated, incomplete or needing a decision

1. **Pin and version.** Specs cite Agent Tools `25f5641` (4.3.0 audited, "setup may install 4.0.3"). Current is 4.6.1+ (fbc5144). GOAL-S03 already says "731e64f or later" for the #42 guards; spec 006/007/009 text and acceptance rows (VIS-04, VIS-05, stale external edit) are now implementable against the guards, but the specs still describe them as open (EXP-02 in 007). The Setup snapshot still pins `hoi4-agent-tools@4.0.3`; the live format-6 manifest is not available locally, so skew between what Setup installs into a mod and what Factory runs server-side is unverified. [V/I]
2. **"Edit property: minimal typed edit" (009 table).** No such upstream operation. The edit unit is the whole focus plan. Factory needs a plan-diff editor layer (state held server-side per session, hashes from `provenance`), and must accept that each edit is a full `focus_rewrite` call with full import + validation + transaction + sidecar write. No latency data exists; VIS-11 / the 100 ms drag-feedback target must be met in the browser with the proposal round trip asynchronous, as 007 already says. [V/I]
3. **Preview before apply (006, 009).** Still no dry-run for `focus_rewrite` or `gui_rewrite`, so the "isolated proposal workspace" approach stands. New since the audit: `map_rewrite` has `preview: true`; event/tech/decision/impact/probability support in-memory `proposedSources` comparison (static what-if without writing); `gui_render` has `sourceBaseline` for before/after pixel deltas. [V]
4. **Expression-based positions (007 VIS-03, 009 "distinguish literal from computed").** The focus importer only understands numeric x/y; I found no diagnostic for `@constant` or other expressions, so such nodes may import as auto or 0 silently. Needs a probe (open question O-3). [I]
5. **Sidecar in the repo.** Spec 009 treats the sidecar as derived data; in practice every national rewrite writes `<file>.focus-plan.json` into the mod. Decide whether Factory keeps it in Git, ignores it, or suppresses it. [V]
6. **Artifact storage.** Spec 006 says artifacts are stored by content hash in the object store; AT's own store is content-addressed under `workspaceStorageRoot` and served as MCP resources. Factory must set `workspaceStorageRoot` outside the repo and decide whether to mirror AT's store or read it through the resource protocol. [V/I]
7. **Icons.** Spec 009 says the browser receives the rendered preview, not game files. Only SVG/HTML/PNG carry icons (embedded data URIs); there is no icon-per-sprite endpoint. A canvas editor that draws its own nodes would need derived icon crops, which touches the game-rights review in 006. [V/I]
8. **Event/decision/tech editors (009 roadmap).** Confirmed read-only upstream; GUI and map do have rewrite tools; so "later editor families" for events/decisions/tech must use plain file edits plus AT compare/lint, while GUI and map can wrap `gui_rewrite` / `map_rewrite`. [V]
9. **Static analysis coverage.** Spec 006 relies on CWTools for parameters/references. Confirmed necessary: `script_validate` sets `parametersChecked: false` and leaves helpers/native argument blocks unresolved. AT does not replace a rule-based validator. [V]
10. **Undo/redo (007).** AT has no inverse operation and hides rollback, so undo must be Factory-level (inverse plan or Git). [V]
11. **Cold start.** Spec has no number for AT start-up; ADR 0045 gives 12-33 s cold on a 2,758-file mod. A per-project worker pool with warm workers (default 180 s idle) or a long-lived HTTP instance is needed for interactive use; spec 006's "supervised worker" model fits but needs a keep-warm policy. [V/I]
12. **Tool naming.** Specs do not name tools; the dotted names need a broker mapping. [I]
13. **Live Tools wording.** Spec 006 says "native Windows/macOS adapters ... unavailable"; accurate for the Rust runtime. It does not mention that the Python Windows package is the only one with event firing, console, log and save tools, which is what a "user-operated observation" import would most likely come from. Also the Python default mode is `campaign` (config.json), which refuses those tools until set to `test`. [V]
14. **Licences.** libvips LGPL notice for a container image; Setup's MPL deps and the wiki snapshot's `not_found` licence if the `paradox_wiki/` is bundled. [V/D]
