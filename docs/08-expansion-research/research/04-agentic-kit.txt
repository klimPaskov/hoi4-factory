## 1. What the kit is, in one paragraph

A source package from which HOI4 Mod Setup (a separate desktop installer, klimPaskov/HOI4-Mod-Setup) installs agent guidance into a user's Hearts of Iron IV mod repository. Claude Code files are canonical: one big always-loaded instruction file (CLAUDE_template.md, placeholders filled by the installer), 32 skills, 23 subagents, a project MCP registration for hoi4-agent-tools, an offline Paradox wiki snapshot (55 pages, 4.2 MB), a deterministic repository check suite (added 2026-10-25), and synchronizers that project the canonical files for Codex, Cursor, Qoder, OpenCode and DeepSeek Harness. Optional workflows (portraits via ComfyUI, 3D models via Meshy+Blender, Super Events runtime, live in-game testing) are manifest components that the installer includes or omits. The repository itself is also a tiny mod skeleton (common/, events/, interface/, localisation/, gfx/ hold only the Super Events runtime sources named hoi4ms_*).

## 3. Skills (32): inventory

Activation mechanism for all of them: the runtime lists each skill's `name` and `description` (frontmatter has only those two keys, no allowed-tools, no disable-model-invocation); the model chooses by description. In addition the always-loaded template names every skill again in its "Repo Skills" block (template lines 88-111). The only gating beyond description text is prose: hoi4-debug-playtest says "Never use unless the user names this skill or explicitly asks for autonomous desktop playtesting" in its description and the template (line 111) says it "is never part of normal coding, validation, audit, or completion routing". Skill descriptions run from 64 to 486 characters; name plus description averages 242 bytes per skill.

Byte sizes below are SKILL.md only. Five skills (feature-assets 57,803; events 56,288; decisions-missions 56,215; feature-planning 55,853; focus-trees 55,761) sit within 0.3 to 3.9 percent of the 58,000-byte cap enforced by .tools/sync/read_limits.json (root_skill_max_bytes).

### 3.1 Workflow and process skills

1. hoi4-events (56,288 B; references/: country-activation.md, event-presentation.md, major-event-aftermath.md, meta-effects.md).
   Activation: "implementing, updating, auditing, or documenting HOI4 events and event chains, including news and report events, on_action hooks, localisation, pictures, registration hooks, and validation."
   Workflow: treats an event as a contract across scopes, on_actions, decisions/focuses, AI chance, pictures, loc and docs (lines 24-39). Classify each block, map touched files by walking outward from the event file (lines 363-405), register optional mod hooks only if the repo has them, deliberate scope handling and "helper output lifetime" for temp variables (459-498), put effects in immediate/option/after correctly, cleanup for every chain (594-612). Mandatory MCP pass: hoi4.event_inspect scan/roots baseline, edit, then compare + lint + render (74-96).
   Verification: final 16-item checklist (310-331), "Validation checks" list including duplicate event ids and referenced events exist (649-674, items are manual), and `python -B .tools/check.py quick` (651).

2. hoi4-focus-trees (55,761 B; references/: completion-rules.md, layout-rules.md, rewards-and-ideas.md, route-design.md).
   Activation: "designing, implementing, auditing, or fixing HOI4 national focus trees."
   Workflow: a design standard (lean opening, branch interaction, no reward dumps, route locks, idea lifecycle, AI, layout) plus an explicit prerequisite-semantics section (lines 72-89: OR is two `focus =` in one `prerequisite` block, AND is separate blocks) and "Do not rely on memory for prerequisite behavior" (line 70). Mandatory hoi4.focus_inspect/focus_render, bounded focus_rewrite; weights go through the probability auditor.
   Verification: audit checklist of about 45 items (lines 893-963), completion-rules.md, `check.py quick` (893) which the skill itself says does not cover route logic or layout.

3. hoi4-decisions-missions (56,215 B; references/: formable-nation-decisions.md, scripted-gui-decision-surfaces.md; templates/formable_state_puzzle/ with README, .gfx, .gui, scripted effects/triggers/GUI/localisation templates, state_manifest.schema.json and example, validation_checklist.md, category_attachment_audit.md).

4. hoi4-feature-planning (55,853 B; references/: 8 files, 112 KB: asset-and-research-handoffs, country-packages-and-formables, final-handoff-and-quality-gate, focus-tree-path-design, forces-and-3d-planning, presentation-and-research-planning, specification-delivery, writing-style).
   Activation: "expanding HOI4 mod feature ideas into detailed specifications before implementation."
   Workflow: turns a rough or partial idea into multi-part Markdown specs under docs/specs/<feature_slug>/ (section 2 "Input": treat the idea as a starting point, expand if rough, preserve direction if detailed; 3.1 idea-first style with a ban on admin sections; 3.2 depth standard; per-surface standards 3.3-3.15). 5. hoi4-improvement-loop (30,719 B; no references).
   Activation: "recursively deepening HOI4 mod mechanics, events, focus trees, countries, decisions, assets, lore, ... into concrete expansion specs and improvement handoffs."

After a feature "compiles" but is thin, write an expansion addendum under docs/plans/<feature_slug>/ via the Opus planner agent; the parent implements, folds into docs/specs/, queues or rejects it before another pass (lines 48-54). 10. hoi4-debug-playtest (25,799 B; no references). Activation: explicit-invocation-only autonomous playtest loop. ## 10. Relationship to Chaos Redux

- scripts/shared_tools.json states "upstream: the Chaos Redux mod repository".
