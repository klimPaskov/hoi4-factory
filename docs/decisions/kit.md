## Decisions

| ID | Date | Question | Decision |
|---|---|---|---|
| D-118 | 2026-11-22 | ZIN's flag lane made every ideology flag of a realm as the same arms with an added border, band, crown or dye. Is that a valid variant? | Not as a default. A variant of a country's flag, emblem, portrait or icon (for an ideology, a route, a cosmetic tag or a formable) is designed with judgment: how would this country really present itself under that government or path, true to its culture, its crown and its history? Often that is a full reimagining. Sometimes a small change is the right answer, for example a communist emblem added to an otherwise kept national flag, as real states have done. What is never acceptable is a mechanical rule that gives every variant the same design with colours or a mark added. The maintainer said this goes for everything in the Agentic HOI4 Modding workflow, so it applies to every mod, not only ZIN. A new variant method gets a small pilot accepted before production. When a country takes on a different identity, for example by forming a formable nation, becoming a puppet in its overlord's manner, being conquered, converting or taking a new dynasty from elsewhere, its flag may break with the old one entirely and is designed from the new identity's own story and culture. Maintainer decision, relayed by the ZIN lead from the maintainer's own words |
| D-152 | 2026-11-27 | The workflow assessment of 2026-11-27 found that one short prompt cannot yet give a complete, playable mod, and listed seven fixes: a new-mod brief with a feature ledger, a completion gate, an in-game test step, the missing writers, model settings, the stale Meshy text and a repeatable benchmark. Start them, and how? | Start them now. Build every fix as a general mechanism that works for any mod idea and whatever model the user runs, and that lands seamlessly in existing installs and projects. Nothing is hardcoded for one model, one prompt or the benchmark. There is no Sonnet-only switch: subagents follow the model the user chose unless a task truly needs another. The benchmark uses several held-out prompts, so the kit is not tuned to one scenario. Maintainer decision |
| D-162 | 2026-11-27 | Design questions for the kit's autonomy fixes (D-152): when the completion gate applies, how a one-line request sets the mod's size, what in-game testing the agent suggests, and when the end-to-end benchmark runs. | The completion gate is active only in projects that started from the new-mod flow and keep a feature list, so existing users and small one-off tasks see no change. A one-line request always aims at the complete mod, built in order: a playable core first (country, map presence, focus tree, first events), then each expansion, so the mod is playable at every step and nothing is cut. When the user answers with the suggested defaults, the agent suggests in-game smoke tests through Live Tools after each finished feature group and before the mod is called done, and a short manual check when Live Tools is not installed. The end-to-end benchmark (several one-line prompts from a fresh Setup mod, checked in the WSL game copy) runs on Sonnet this week as the fixes merge, and the kit is fixed from each run. Maintainer decision |
| D-170 | 2026-11-28 | Kit PR 204 made every content subagent inherit the session's model. Is that the rule? | No. Subagents are used as needed, each on the model its task needs (for example Haiku for mechanical work), not forced to the session's model. The ceiling is for helpers: new chats or sessions, orchestrators and similar agents that an agent starts never start on a higher model than the model the user's chat started on. So a run the user started on Sonnet never escalates to Opus or Fable by itself. Refines what kit PR 204 shipped. Maintainer decision |
| D-171 | 2026-11-28 | The brief, feature list and completion gate apply only to new mods, because D-162 limited the gate to projects started with a feature list. Should they also cover bigger requests on an existing mod? | Yes. Any big request on any mod, new or existing (for example a new nation, a focus tree or an event chain), gets a brief and a feature list for the requested work, scaled to its size, and the completion gate checks that work before the agent says it is done. Small edits stay light, with no brief or gate. The kit decides big or small by a general rule, never by one model, prompt or mod. Widens D-162. Maintainer decision |
