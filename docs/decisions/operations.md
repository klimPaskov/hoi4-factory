## Decisions

New entries go here in full, oldest first. A decision that spans projects is written here, with a line in each affected project file.

| ID | Date | Question | Decision |
|---|---|---|---|
| D-33 | 2026-11-08 | May agents start the game without a new approval each night? | Yes, under one standing rule that replaces the dated night windows. On the Windows PC the game may be started on any night from 00:00 to 06:00 local, while the maintainer is not using the PC. Only one runner session starts it, one instance at a time, through HOI4 Live Tools with the launch checks the machine's Live Tools setup requires. With a coordinator running, the coordinator names the runner. Without one, the first session that needs a check takes the role and logs it in `.work/overnight-summary.md`, and every other session sends its checks to that runner. The runner backs up and restores the user-folder files a launch rewrites, never touches saves or real mod source, never loads ZIN on Windows, reads each loaded mod's own rules first, starts no new launch after 06:00 and has the game closed and the files restored by 06:15. The isolated WSL Linux copy of the game may be started at any time under the same conditions, one instance at a time under the shared WSL lock, with no console, save or memory edits. A mod's own rules still decide whether it may be loaded, so ZIN stays unloaded unless ZIN's rules or a maintainer decision allow it, as D-29 did. The maintainer can cancel any night by saying so. Outside these windows D-17 applies. D-29 and D-30 keep their own terms until they end on 2026-11-09. Maintainer decision |
| D-34 | 2026-11-08 | Are work sessions capped? | No. D-31 stands: live sessions are not capped. The coordinator archives finished sessions promptly, runs one heavy job at a time (Blender, the game or a large Rust build) and resumes paused sessions after a crash. The CLAUDE.md line that told the coordinator to keep about six sessions live contradicted D-31 and is removed. Maintainer decision |
| D-35 | 2026-11-08 | How are decisions recorded so later sessions find them? | In two layers. This folder holds one file per project: operations, HOI4 Factory, Agent Tools, the kit, Setup, Live Tools, hoi4-imagegen, the 3D route and the mods. Each file starts with the decisions in force for that project, one line each with a link to the full entry, and lists replaced and expired decisions apart. New decisions are written in full in the file of the project they govern. IDs continue as one global D- sequence so they stay unique. The expansion research record and the 2026-10-24 maintainer record become history and are not rewritten. The [README](README.md) is the entry point, and CLAUDE.md points to it. Maintainer decision, with the layout chosen by the recording agent |
| D-36 | 2026-11-08 | What gets the most attention until about 2026-11-22? | Tools for other modders. Three goals run together: a modder installs through HOI4 Mod Setup and has a working agent with every tool within minutes, proven by fresh-install tests on Windows and Linux. HOI4 Agent Tools gains more coverage (the R-5 modder features and the R-4 profiles). hoi4-imagegen makes better images (family fixes, model routing, palette variety, the TFR style packs). In-game testing through HOI4 Live Tools comes after these three. S04 keeps one work session at low priority: tool sessions get the heavy jobs and the maintainer's time first, and S04 never holds up a tool release. 3D production stays paused (3D-11, 3D-12, D-37). Maintainer decision |
| D-39 | 2026-11-08 | How much of the usage limit may agents use? | The coordinator reads usage at every check-in and starts no new work session once about 80% of the weekly usage limit is used, so the rest stays for the maintainer's own work. Sessions already running finish their current step and then wait. Without a coordinator, a session checks usage before it starts long work and stops at the same level. The maintainer may lift the limit for a given push. Maintainer decision |
| D-53 | 2026-11-08 | Which models and efforts do sessions use? | Each session and worker gets a model and effort that fit its work, never everything on Opus at the top effort. Effort stays at high or below, so extra high and max are not used. Sonnet does structured and mechanical work at medium or high, and Opus at medium is kept for design-heavy work or a new subsystem. A coordinator passes model and effort on every start and lowers any session it finds above high. Maintainer decision |
| D-54 | 2026-11-09 | Should hoi4-imagegen-mcp stay a GitHub fork of Connected-Mate/gptimage? | No. The maintainer wanted it as their own repository with the same name so no links break. It was backed up in full, deleted and recreated as a non-fork, and its branches, tags, all 13 releases with byte-identical files, labels, the open issues and the open pull requests were restored. Closed pull request pages, stars and the old release attestations could not be kept, and issue and PR numbers restarted at 1. The credit to the original project stays in the README and licence. Maintainer decision |
| D-40 | 2026-11-08 | How do tool releases reach modders? | More slowly, and cleanly when promoted. HOI4 Agent Tools, hoi4-imagegen, HOI4 Live Tools, the kit and HOI4 Mod Setup each ship feature releases at most about once a week. Fixes for broken installs or wrong results ship any time. After a week's tool releases the kit pins them once, and Setup releases once after a fresh-install test on Windows and Linux. When the maintainer promotes a tool, for example once a trailer is finished, the promoted tool and everything that installs it are released at their latest version first, and its public text is cleaned: the README, docs, release notes, gallery, repository description and Setup's own text are current, accurate and short, with no internal notes, dated incident stories or private material. The `prepare-promotion-release` skill holds the steps. Agents prepare and the maintainer promotes (R-12). Maintainer decision |
| D-41 | 2026-11-08 | What is researched next? | A fresh scan of HOI4 AI and modding tools that appeared or changed since October 2026, compared with ours on features, accuracy and ease of install. It is read-only, with no accounts and no posts. It feeds the Agent Tools and kit priorities and the Q-1 comparison set. Modder pain points, 3D tools and hosting cost are not researched now. Maintainer decision |
| D-42 | 2026-11-08 | Should CLAUDE.md be slimmed? | Yes. Every rule stays in CLAUDE.md as a short line. Dated incident stories and one-time history move to a linked lessons file under `docs/07-developer-workflow/`, so the reason behind each rule can still be found. A diff audit proves that no rule was lost, as P11 required for the kit. Maintainer decision |
| D-43 | 2026-11-08 | Which promotion comes next? | The whole modder workflow: HOI4 Mod Setup, the kit and every tool it installs, promoted as one package once the three tool goals of D-36 land. Agents prepare it during the tool push under D-40, with the latest releases, clean public text, the macOS results of D-47 once the maintainer has run them, and a video draft under D-49. Maintainer decision |
| D-46 | 2026-11-08 | Where does the main effort go after the tool push? | To restarting the 3D route around 2026-11-22: the bake-off result, the open lessons under D-37, then new units through the tools-and-presets route (3D-11, 3D-12), and a new trailer once the maintainer approves units (3D-15). S04 keeps its one low-priority session until the maintainer changes that. Maintainer decision |
| D-47 | 2026-11-08 | How do the macOS-only checks run? | Through one self-contained prompt that the maintainer gives to a Claude Code agent on the Mac, [GOAL-MACOS-CHECKS](../06-agent-handoffs/GOAL-MACOS-CHECKS.md). The maintainer runs it when at the Mac. Maintainer request, prompt written by the recording agent |

| D-49 | 2026-11-08 | Who makes promotion videos such as trailers? | An agent drafts each video from real captures, and the maintainer reviews it before anything is posted. Agents never post or upload (R-12). The visual review rules still apply before the maintainer sees it. Maintainer decision |
