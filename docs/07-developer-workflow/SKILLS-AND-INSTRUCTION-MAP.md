# Skills and instruction map

Status: Proposed starter with static integrity checks. Owner: engineering guidance maintainer. Current documentation checked 2026-10-23. No client loading or model trigger trial has run in this planning environment.

## One logical policy and one workflow body

| Artifact | Authority and purpose | Owner |
|---|---|---|
| Root [CLAUDE.md](../../CLAUDE.md) | Canonical project instructions: rules, reading order, environment, delegation, external services, skills | The implementing agent, under ADR-024 |
| Root [AGENTS.md](../../AGENTS.md) | Byte-identical copy of CLAUDE.md generated by `sync_skills.py` for clients that read AGENTS.md | Generated, never edited |
| Approved stage packet | One stage's scope, dependencies, experiments and exit criteria | Stage owner |
| Accepted decisions and specs | Design rationale and intended behavior | Product and architecture owners |
| `docs/07-developer-workflow/skill-workflows/<name>/BODY.md` | Canonical tool-neutral procedure | Engineering guidance maintainer |
| [skills.json](skills.json) | Canonical names, descriptions and invocation metadata | Engineering guidance maintainer |
| `.claude/skills/<name>/SKILL.md` | Generated Claude wrapper and canonical body | Generated, review source instead |
| `.codex/skills/<name>/SKILL.md` | Required portable counterpart in the archive | Generated compatibility copy |
| `.agents/skills/<name>/SKILL.md` | Current Codex repository discovery mirror | Generated discovery copy |
| `evidence/SNN/` | Actual future stage evidence and handoff | Implementing agent and reviewer |

The seven workflows are `start-implementation-stage`, `validate-stage`, `capture-engineering-lessons`, `audit-hoi4-integrations`, `production-readiness-review`, `delegate-parallel-work` and `ui-design-iteration`. `ui-design-iteration` is the preview-and-choose loop for client pages (ADR-025). The agent creates further skills when a workflow repeats (ADR-024). `delegate-parallel-work` covers worktrees, subagent briefs, merging and cleanup. `production-readiness-review` treats the [production readiness checklist](../05-verification/PRODUCTION-READINESS-CHECKLIST.md) as a menu of considerations, not requirements, and recommends only proportionate, low-friction hardening. It never blocks a stage or release by itself. All three trees contain real SKILL.md files at the project root. No symlinks or global installation are required. The generator renders each canonical body and rebases its local Markdown links for the generated file's location. The three client trees share the same rendered body because they have the same directory depth. Client-only frontmatter and metadata may differ intentionally. Review the canonical source, regenerate the projections and check their exact generated bytes instead of copying canonical relative links unchanged.

## Verified discovery and invocation

Current Claude memory documentation supports the explicit AGENTS import. Native AGENTS discovery was added in v2.1.277 and can depend on other instruction files and configuration. The import avoids assuming those conditions or changing a global switch. Use the installed client's instruction inspection UI to confirm loading in S01. [Claude memory](https://code.claude.com/docs/en/memory)

Claude discovers project `.claude/skills` and supports `disable-model-invocation: true`. The starter sets this field on `start-implementation-stage` and `audit-hoi4-integrations`, which only the maintainer invokes with `/skill-name`. Under ADR-023, `validate-stage` and `capture-engineering-lessons` omit it so the agent can run them at every handoff. The Codex sidecars follow the same split through `allow_implicit_invocation`. It does not use `allowed-tools`, which grants preapproval rather than acting as a general tool restriction. No model pin or tool name is placed in shared bodies. [Claude skills](https://code.claude.com/docs/en/skills)

Current Codex repository discovery uses `.agents/skills`. The requested `.codex/skills` tree is preserved but is not claimed to load automatically. Codex sidecars use `policy.allow_implicit_invocation: false`, so explicit `$skill-name` remains available. Do not configure duplicate discovery of both mirrors. [Codex skills](https://developers.openai.com/codex/skills)

Root-to-working-directory AGENTS discovery and the configured instruction budget are client behavior. The starter's 184320-byte Codex ceiling is not a target document length or model context window. Launch from the repository root and check for existing overrides before concluding the shared policy loaded. [Codex instruction discovery](https://developers.openai.com/codex/guides/agents-md)

For a larger implementation repository, Claude-specific rules may live in `.claude/rules/*.md` with `paths` frontmatter scoped to matching project-relative files. Rules without `paths` load generally, and malformed frontmatter can remove the intended scope. Validate the header and matching behavior in the installed client. Keep shared policy in AGENTS and document the corresponding directory guidance for other clients rather than assuming identical discovery. This starter ships no extra rule files before module boundaries exist. [Claude path-specific rules](https://code.claude.com/docs/en/memory#path-specific-rules)

## Maintenance commands

From `hoi4-factory/`, with Python 3.11 or newer:

```bash
python scripts/sync_skills.py --check
python scripts/validate_package.py --root . --working-tree
```

After reviewing a change to canonical bodies or metadata:

```bash
python scripts/sync_skills.py --write
python scripts/sync_skills.py --check
```

Write mode changes only the named generated skill trees and hash manifest inside this repository. It refuses symlinked managed paths. It does not install skills into a personal client directory. Inspect the resulting diff and include the canonical edit, generated copies, updated tests and knowledge changelog in the same review. Check mode is read-only and is the default.

The validator's default mode checks the untouched distribution against `docs/MANIFEST.json`. Use `--working-tree` for evolving project documentation and guidance after adding evidence or product files. This mode retains structural and skill checks while skipping frozen distribution hashes. Neither mode is a substitute for the approved stage's product tests.

## Trigger and boundary checks

[skill-trigger-fixtures.json](skill-trigger-fixtures.json) contains positive, negative, missing-input and scope-boundary scenarios. Each fixture identifies the expected workflow and behavior. These are evaluation cases, not recorded model results. Static checks confirm structural metadata, canonical hashes and intentional invocation settings. S01 runs the fixtures with installed clients and records actual traces.

Pass requires the correct workflow, its required inputs, evidence labels and stage boundary. An ordinary question must not start implementation. An explicit skill call without a stage authorization may prepare a read-only proposal but must not create product files. A completed stage must hand off rather than start the next stage. Unavailable tools produce a precise limitation without inventing output or blocking unrelated approved work.

## Adoption into an existing repository

The extracted `hoi4-factory/` folder is ready to use as the working project folder. Its client files are already in place, so ordinary S01 setup verifies and adapts them there. If incorporating the starter into a different existing repository, read its ancestor and directory guidance first, inventory current skills and config, and compare the starter as a proposed diff. Resolve policy conflicts with the owner and preserve team-specific rules. If equivalent skills already exist, adapt the canonical sources and map the names instead of creating duplicate activation paths. Record the final instruction map and actual client versions.

The upstream Agentic package uses CLAUDE as canonical source and generates AGENTS. This starter deliberately uses the requested shared AGENTS authority and explicit CLAUDE import. The reuse is the tested projection discipline, not an identical authority hierarchy.
